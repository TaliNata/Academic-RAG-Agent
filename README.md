**Telegram-бот с RAG-пайплайном для работы с научными статьями**

Агент средней сложности: загружает документы в векторную базу, ищет по смыслу, генерирует ответы с указанием источников.

---

## Задача

Дать исследователю возможность загрузить набор научных статей и задавать вопросы по их содержанию — без необходимости перечитывать каждую статью вручную.

## Что умеет бот

| Функция | Описание |
|---------|----------|
| Загрузка статей | Отправьте PDF или TXT — бот извлечёт текст, разобьёт на фрагменты и сохранит в векторную базу |
| Вопросы по базе | Задайте вопрос — бот найдёт релевантные фрагменты и сгенерирует ответ с указанием источников |
| Обзор литературы | Укажите тему — бот составит обзор на основе загруженных работ |
| Управление базой | Список статей, статистика, очистка базы |
| Выбор модели | Переключение между LLM прямо в чате |

## Структура проекта

```

├── bot.py              # Telegram-бот: команды, загрузка файлов, обработка вопросов
```

## Стек технологий

| Компонент | Технология | Зачем |
|-----------|-----------|-------|
| Язык | Python 3.11+ | Основа проекта |
| Telegram API | aiogram 3 | Асинхронный бот-фреймворк |
| Векторная БД | ChromaDB | Локальное хранение эмбеддингов, персистентность |
| Эмбеддинги | all-MiniLM-L6-v2 (через ChromaDB) | Семантический поиск по фрагментам |
| Парсинг PDF | pdfplumber | Извлечение текста с сохранением структуры |
| LLM API | OpenRouter + OpenAI SDK | Мультимодельный доступ через один эндпоинт |
| Валидация | Pydantic + pydantic-settings | Конфигурация и типизация |

## Ключевые технические решения

**Чанкинг с учётом абзацев.** Текст разбивается не механически по N символов, а по границам абзацев. Длинные абзацы дополнительно разрезаются по предложениям. Перекрытие 200 символов между фрагментами сохраняет контекст на стыках.

**Изолированные коллекции.** Каждый пользователь Telegram получает свою коллекцию в ChromaDB (`user_{id}`). Базы знаний не пересекаются.

**Контроль контекстного окна.** При формировании промпта для LLM фрагменты добавляются по релевантности, пока не исчерпан лимит (6000 символов). Это гарантирует, что промпт не превысит контекстное окно модели.

**Прогрев при старте.** ChromaDB при первом запуске скачивает модель эмбеддингов (~80 МБ). Прогрев вынесен в фазу инициализации, чтобы первый запрос пользователя не уходил в таймаут.

**Неблокирующие операции.** Парсинг PDF, создание эмбеддингов и поиск по базе — CPU-bound операции. Они обёрнуты в `asyncio.to_thread()`, чтобы не блокировать event loop бота и не вызывать таймауты Telegram API.

**Автоопределение заголовка.** При загрузке статьи бот пытается определить название из первых строк текста — по эвристике (длина, наличие точки, позиция).

## Отличия от простого агента

| Параметр | Простой агент | RAG-агент |
|----------|--------------|-----------|
| Хранение данных | Нет | ChromaDB (персистентное) |
| Обработка файлов | Нет | PDF + TXT парсинг |
| Пайплайн | Промпт → LLM → ответ | Парсинг → чанкинг → эмбеддинг → поиск → контекст → LLM |
| Контекст | Только текст сообщения | Релевантные фрагменты из базы |
| Источники | Нет | Указываются в ответе |
| Масштабируемость | 1 текст за раз | Множество документов |

## Как запустить

1. Создать бота через [@BotFather](https://t.me/BotFather)
2. Получить API-ключ на [openrouter.ai](https://openrouter.ai)
3. Заполнить `.env` (по шаблону `.env.example`)
4. `pip install -r requirements.txt`
5. `python bot.py` (первый запуск — прогрев модели эмбеддингов ~80 МБ)
